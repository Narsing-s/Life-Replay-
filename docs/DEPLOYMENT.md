# Deployment Guide

## GitHub Pages frontend

For the static Memory Atlas frontend:

1. Open repository **Settings → Pages**.
2. Choose **Deploy from a branch**.
3. Select branch `main`.
4. Select folder `/(root)`.
5. Save.
6. Wait for the Pages deployment to complete.

Expected URL:

`https://narsing-s.github.io/Life-Replay-/`

The frontend uses the configured production backend when running on the GitHub Pages hostname.

## Render backend

The repository contains `render.yaml` for the Node/Express service.

Required production settings:

- `JWT_SECRET`: long random secret generated by the hosting platform.
- `DATA_DIR`: persistent data directory.
- `ALLOWED_ORIGINS`: include the exact production frontend origin.
- Persistent disk mounted at `/app/data` when using SQLite/uploads.

Health check:

`GET /api/health`

After deployment, verify the health endpoint before testing registration or login.

## Docker

Build:

```bash
docker build -t life-replay .
```

Run with persistent storage:

```bash
docker run --name life-replay \
  -p 4173:4173 \
  -e JWT_SECRET="replace-with-a-long-random-secret" \
  -v life-replay-data:/app/data \
  life-replay
```

## Troubleshooting

### Browser says `Failed to fetch`

Check these in order:

1. Backend is running.
2. `GET /api/health` returns successfully.
3. The frontend backend URL is correct.
4. `ALLOWED_ORIGINS` contains the exact frontend origin.
5. HTTPS is enabled for the deployed frontend and backend.
6. Browser developer tools do not show a CORS, DNS, TLS, or mixed-content error.

### Login/register returns non-JSON

Verify that `/api/auth/login` or `/api/auth/register` is reaching the backend rather than the static GitHub Pages server.

### Data disappears after restart

The backend is using ephemeral storage. Configure a persistent disk/volume for `/app/data` or migrate the storage layer to managed PostgreSQL and object storage.
